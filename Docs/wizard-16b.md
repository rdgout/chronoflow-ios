# Phase 16b: member return, sleep and review

The member wizard now continues from Outbound through Coming back?, the optional flight home, required first-time Sleep, Checking, server questions and exclusions. A successful review with no remaining blocking questions reaches the Debug-only Phase 16c seam. Fine-tune, Ready and saving remain Phase 16c; no new API endpoint or shipping stand-in is introduced.

Return supports one-way, a flight home and preserving a pre-existing website nights/check-out end. A new return starts with empty dates, departs from the final outbound airport, and initially flies to the outbound origin. Only its destination can be changed; the departure airport stays fixed. Return stops use the existing airport search and native flight pickers. Past uses the final trip arrival in its airport's zone after Checking, so a past outbound with an upcoming return remains valid. Outbound validation ignores incomplete return fields when navigating back.

Sleep stays required while the account's `sleepAnswered` is false. The account supplies existing sleep values; both times and an explicit chronotype choice are required, including Not sure (`null`). The RN 3–14 hour sleep-duration rule applies. A successful profile-bearing review uses Phase 13's existing account adapter, preserves pending body-clock patches and updates `sleepAnswered`. Review effects hold the session mutation permit through the SQLite transaction. Their lifetime is independent of foreground sync; cancellable writes use child epochs, and revoked session permits reject late writes.

Checking uses an injected monotonic clock: ticks at 400/800 ms, the response tick at or after 1.2 seconds, then a 300 ms pause. Slow appears at ten seconds; thirty seconds produces the designed server failure. Request-derived offline remains distinct. The server's retry-after value drives the visible ceiling countdown and disables retry until zero; zero/absent waits leave retry enabled. Review and its effects are cancelled on back/close, with attempt guards dropping late results. Choice taps select immediately, ignore additional taps and advance after 250 ms.

Questions retain the server's blocking prompt list, order, target fields, options and review identity. Blocking kinds are AgeBand and Screening (shift work only), per server Phase 19. Medical questions are removed; caffeine exclusion and flight movement breaks are neutral preferences in Fine-tune. Audience and light-device cautions are text only. Answers advance through the questions and then re-review with profile values. Exclusions display server reasons and can clear exclusion-causing answers before checking again. Recovery retains the review, question position, answers and last input step. Checking hides its chevron while retaining the system edge-swipe; the first question goes back to the last input, skipping Checking. Progress holds when more questions are added. Native scrolling/safe-area layout and the existing root Dynamic Type cap remain in use.
